尚未覆盖的能力

按对源目录功能等价的优先级排序

Ornn skill 与 Lark Bot 启动

P0 未覆盖

尚未在新仓库完成 skill 打包、发布、搜索、加载，以及 Bot 通过自然语言选中并启动 workflow 的 typed 全链路。

Durable schedule

P0 阻塞

08 和 10 的业务分支已通过，但 production durable preview 返回 DURABLE_AUTHORIZATION_UNAVAILABLE 或 NYXID_EXPLICIT_REQUEST_INTERACTIVE_REQUIRED。

Webhook HTTP 契约

P1 未覆盖

交互式 workflow invoke 替代了触发入口，但没有证明 n8n webhook listener 和 respondToWebhook 的同步 HTTP 行为。

图片与 PDF OCR

P1 部分

附件、提取和 LLM 已通过，公开 fixture 仍只有合成文本，没有覆盖图片/PDF 媒体输入质量与 OCR。

发票专属财务规则

P1 部分

当前验证材料完整性和访问审批，不覆盖供应商归一化、金额/币种、发票号与财务重复提交规则。

Lark contact batch lookup

P2 替换

绑定 Bot 缺少 contact:user.id:readonly，案例 09 使用 Base 身份目录。业务身份解析可用，但 contact API 本身未通过。

通用 code_execute

P2 有意移除

production 返回 NYXID_PROXY_UNAUTHORIZED。01-10 已改为原生确定性节点；这不等于通用代码执行能力得到验证。

本轮真实运行修复

均由失败证据驱动，而非只修静态定义

Scriban 与运行时兼容

修复多余 end、空 Base 省略 items、受限 Scriban 不支持 string() 等问题。

工具 receipt 路径

05、07 改为读取当前 typed receipt，不再提取迁移前的 output.stdout。

SSE 审批恢复

生产验证器改为逐行消费 SSE，pending receipt 到达后立即 resume，并限制诊断缓冲为 64 KiB。

审批历史与幂等

09 不再假定 page_size=1 是最新记录，修正动态时间窗，并按多条 foreach 输出逐行判断。

多源输出归一化

08-10 显式处理各工具响应和 foreach 串联格式，避免把多条 JSON 当成一个对象。

分支复测入口

新增单案例 --prompt，同一定义已复测 09 幂等和 10 的月末、跳过、提醒分支。

#3182 证据边界

#3182 关注的是工具失败后 Bot 仍可能用自然语言误报成功，不是 code_execute 授权错误本身。11 个直接 workflow committed 成功，不能外推为 Ornn + Lark Bot 自然语言链路已经通过。
