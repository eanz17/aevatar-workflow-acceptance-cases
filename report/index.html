/api/chat 与 Lark Bot 的边界

共享核心能力，不共享完整 transport

/api/chat 已覆盖

  • NyxID 用户身份和 scope
  • Assistant / AgentRun 与工具目录
  • Ornn 搜索和 skill 加载
  • workflow 启动与 artifact 查询工具
  • SSE 直接返回调用方

Lark Bot 已覆盖

  • Lark webhook 与事件转换
  • NyxID channel relay 和 active Bot
  • conversation 到 agent 的映射
  • 发送者身份解析
  • 文件卡片、附件解析与 reply relay

不能外推

/api/chat 成功不能替代 Lark Bot transport 证据；Lark 回复也不能证明 workflow committed 成功。案例 14 的三次 Bot run 均因 resource narrowing committed failed；案例 19 的文件卡片、解析与回复 relay 已验证，但 Assistant catalog 没有可启动定义，三次 start 均为 service_catalog_missing 且 run 增量为 0。Case 20/21 只有在真实 Lark skill mount 审批回调分别取得 approved committed artifact 与 rejected Denied receipt 后才能通过；Case 22 还必须独立证明 workflow 运行期审批卡和同一 run continuation。
